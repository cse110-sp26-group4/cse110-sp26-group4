The issue tracker built for AI agents.

Baton is a terminal-first issue tracker for the AI-augmented workflow. Human supervisors plan the work; autonomous agents pick it up, do it, and submit it for approval. Everything from the command line, all kept honest by a strict review loop and a full audit trail.

Get started See what it does
npm install -g baton-issue-tracker

What is Baton?

When AI does much of the heavy lifting on a codebase, you need a single place that decides what gets worked on and a reliable record of who did what. Baton is that place. It stores every issue in a local SQLite database (.baton/baton.db) right in your project. No external cloud service needed, just right there in your repo alongside your code.

Every command speaks two languages: clean, human-readable output for people, and structured --json for agents to parse. The result is one source of truth that humans and AI can share without stepping on each other.

Features

AI-native API

Every command supports a --json flag, so agent loops can read and write issues without scraping text.

Human-in-the-loop

A strict state machine means agents can submit work, but only a human can approve it. Nothing closes without a review.

Full activity history

Every claim, edit, submission, and status change is logged. Run baton log <id> to see exactly what happened.

Token budgets

Assign a token limit to any issue to keep agent costs visible and under control.

Zero-config storage

Issues live in a local SQLite file inside your repo. Clone the project, run init, and you're tracking.

Explicit issue claiming

Agents run baton claim <id> to take ownership of a specific issue and move it to In-Progress.

How it works

Every issue moves through the same predictable lifecycle.

Open → In-Progress → In-Review → Closed

An issue in review can be sent back to In-Progress if changes are requested.

  1. Plan. A human supervisor creates issues by hand, or seeded automatically from a requirements file during baton init.
  2. Claim. An agent runs baton claim <id> to take ownership of a specific issue, moving it to In-Progress.
  3. Do the work. The agent reads the issue with baton view <id>, makes the changes, and tests them.
  4. Submit. The agent runs baton submit <id> to send the finished work for human review.
  5. Approve or reject. The human reviews and either baton approve <id> to close it, or baton reject <id> with a reason to send it back.

Quickstart

Up and running in under a minute. Requires Node.js 22+.

# 1. Install Baton globally
npm install -g baton-issue-tracker

# 2. Initialize a tracker in your project
baton init

# 3. Register yourself as a supervisor
baton register --name "your-name" --type human

# 4. Create your first task
baton create --title "Fix login bug" --priority high

# 5. Check the board anytime
baton status
